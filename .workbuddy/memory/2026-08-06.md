### 🔧 根因修复：Post-actions 后台上传被 Xcode 回收进程树（"传不上去"的真正原因）
- **现象**：xiyuScoreboard 接入后 Archive 显示成功，但蒲公英永远收不到包；Post-actions 路径的 `pgy_upload_*.log`/`pgy_monitor_*.html` 根本未生成（进程被秒杀，未写任何文件）。AI/CLI 路径（`archive_upload.sh --target`）却全程成功 → 证明引擎导出/上传逻辑本身没问题，纯属运行时进程管理。
- **根因**：原 Post-actions 后台启动用 `nohup bash ... &`，子进程仍属 Xcode 的进程组/会话；Archive 动作一结束 Xcode 回收整个进程树，把上传子进程一并 kill。
- **修复（commit ce8fd55）**：改用 `python3` 的 `os.fork()` + `os.setsid()` 先把上传子进程切到全新会话，再 `os.execv("/bin/bash", ["bash", self] + args)` 运行自身；父进程（python）立即 `sys.exit(0)`，Run Script 秒退、Archive 立即完成。子进程 stderr→/dev/null（避免与 `log()` 的 `>>LOG_FILE` 重复写），stdout→日志文件。
  - macOS 无 `setsid` 命令，故用 python 实现；`execv` 直接执行带 shebang 脚本会 `PermissionError(13)`，必须用 `/bin/bash` 显式执行。
- **实证**：用相同修复版模拟 Post-actions 脱离，子进程存活并完整跑完 `xcodebuild -exportArchive`（xiyu_scoreboard.ipa 7.4M）→ curl 上传 → `🎉 上传成功: https://www.pgyer.com/xiyujifenban`。坐实修复有效。
- **README**：新增「排查：Archive 显示成功，但蒲公英永远收不到包」章节（含自检清单 + 严禁 `kill -9 -PGID` 模拟回收）。
- **⚠️ 安全教训**：曾用 `kill -9 -$PGID` 模拟 Xcode 回收，PGID 恰为 Bash 工具自身会话组 → 工具 shell 被 SIGKILL 自杀。绝不再对任意 PGID 盲目 `kill -9 -PGID`，改用按 PID 精确停止。
