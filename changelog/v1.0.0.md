# v1.0.0 — 建立项目治理基线（CR-001）

- 类型：规范性变更（治理机制建设，无运行行为改动）
- 日期：2026-09-19
- 关联：CR-001
- 来源：由 `xiyu-project-governance` 脚手架生成

## 背景

`archive-pgy-uploader` 是一份**共享引擎**：把「Xcode Archive → 导出 IPA → 上传蒲公英」整链路脚本化，
宿主 iOS 项目以 git submodule 引入，各自只持有自己的 `pgy_config.sh`（密钥）与 `PGYUploadHistory.json`（是否上传 + 版本信息）。
截至基线建立时，它已被 3 个项目实际使用（`xiyuScoreboard` / `xiyu_todo_list` / `xiyuWebBrowser`），
且其中 2 个项目的接入过程都踩过同一类坑（Xcode 不热加载共享 scheme、`--notes` 与 Post-actions 入口的语义差异）。

本项目需由多个 Agent 在多个会话、多个客户端（WorkBuddy / Kiro / Codex / Cursor）中接力开发，
而这些踩坑结论此前只散落在会话记忆与 `README` 的长段落里，无法保证下一个接手者读到。
故先建立单一事实来源与变更痕迹机制，再继续演进代码。

## 内容

1. **`STATUS.md`** — 实现真相索引 + 交接主文档（YAML frontmatter + 9 章正文）。
2. **`changelog/CHANGES.md`** — `CR-NNN` 追加式变更流水（含前后差异、影响范围、兼容性、验证方式）。
3. **`changelog/CHANGELOG.md` + `changelog/v1.0.0.md`** — 版本索引与首份版本档案。
4. **`experience/`** — `INDEX.md`（使用说明）、`LESSONS.md`（`L-NNN` 经验）、`execution-log.json`（`run_id` 日志）。
5. **`AGENTS.md`** — 跨工具入口：读取顺序、变更控制协议、交接速览。
6. **`.gitignore`** — 忽略依赖/构建产物与 `.env*`（保留 `.env.example`）。

## 效果

- 任何 Agent 接手时读 `AGENTS.md` → `STATUS.md` → `experience/LESSONS.md` 即可获得完整上下文。
- 每次改动有据可查（CR-NNN），版本可追溯（vX.Y.Z），踩坑经验可复用（L-NNN）。

## 版本号语义

本项目在基线前**没有版本号体系**（无 git tag，脚本内无版本常量）。
`v1.0.0` 不表示"发布版本"，而是**建立治理基线时的现状快照**——即当时 HEAD 所具备的能力集合（`STATUS.md` §2.1 的 C1–C10）。
后续按 `STATUS.md` §8.4 递增，且遵循「只有影响宿主调用行为的改动才升版本」。
