# v1.3.0 — 「半套接入」的检测与自动补登

- **发布日期**：2026-09-19
- **版本类型**：次版本（新能力 + 行为扩展）
- **变更条目**：CR-007
- **上一版本**：v1.2.0

## 一句话

`sync-hosts.sh` 现在能识别并**自动补登**「`.gitmodules` 已入库、但 gitlink 未登记」的宿主——
这种状态本地看不出异常，但新克隆会**静默**缺少引擎子模块。

## 背景：一种本地看不出来的坏状态

上一轮真实修复 `xiyu_todo_list` 时遇到：`.gitmodules` 已在 HEAD，但 gitlink 既不在索引也不在 HEAD
（`git submodule status` 为空）。当时只能手工 `git add <子模块路径>` + commit。

本地 `git status` 只把该目录显示成**未跟踪**，没有任何异常提示。而危害实测如下：

| 状态 | 新克隆后 `git submodule status` | 子模块目录 | `submodule update --init` 退出码 |
| --- | --- | --- | --- |
| 半套接入（未修） | **空**（git 完全不认识该路径） | **不存在** | **0（不报错、也不检出）** |
| 已补登 | `<sha> sub (vX.Y.Z)` | 存在（引擎全部文件） | 0 |

即：**不报错、静默不检出**，直到构建时才发现引擎脚本缺失——比直接报错更难查。

## 新增

| 项 | 说明 |
| --- | --- |
| 状态 `unregistered-gitlink` | 与 `not-a-submodule` 区分：前者是「登记不完整」，后者是「根本没有子模块」 |
| `--apply` 自动补登 | `git add -- <子模块路径>`（对嵌仓库即写模式 `160000`）+ 本地 commit |
| 补登时对齐版本 | 落后于目标 → 先 `fetch` + `checkout --detach <目标>` 再补登；`ahead` → 按当前 HEAD 补登；`unknown`/`diverged` → 只补登并提示版本关系未定 |
| `.gitmodules` 一并提交 | 仅当它还没进 HEAD 时（否则不动它，实测提交恰为 1 行 gitlink 变更） |
| JSON `summary.unregistered` | 新增计数字段 |
| JSON `status: "unregistered"` | `--check` 下存在该状态时返回（位于 `outdated` 之后、`attention` 之前） |
| `--check` 退出码 | `UNREG>0` → `2`（与 `outdated` 同级：可被 `--apply` 修复） |

## 安全边界（刻意不做的事）

1. **只对真正的子模块 checkout 补登**：判据是新函数 `is_submodule_checkout()`——子模块的 git dir 必须落在宿主的
   `.git/modules/` 下。随手放进目录的 **vendored 副本 / 嵌套仓库不会被误补登**（补登它们的 HEAD 会立刻变成
   `unknown-engine-commit`，制造「已登记」的假象）。这类宿主仍报 `not-a-submodule` 并提示走 `git submodule add`。
   已用反向对照夹具实测：vendored 宿主补登后 `git ls-files -s -- vend` 仍为空。
2. **`uncommitted-gitlink` 不自动处理**：那是「人已 `git add`、只差 commit」，可能处于人工编辑中间态，
   由人决定何时提交更稳妥。
3. **子模块工作区脏 / 宿主工作区脏** 仍默认跳过（沿用 v1.1.0 语义，`--allow-dirty` 才越过后者）。

## 同批修复的既有缺陷：`--apply` 的 tab 折叠串列

被新状态的夹具照出来的**既有**缺陷。`rows.tsv` 以 `\t` 分隔，`pinned` 为空时写出连续两个 `\t`；
而 **tab 属 IFS 空白字符 → bash 的 `read` 会把连续分隔符折叠成一个**（`jq` 的 `split("\t")` 不折叠，
所以二者行为不同）。后果是 `--apply` 循环内其后**所有列左移一格**：`state` 变成 `N`、
ACTION 变成 `skip:<dirty值>`，并原样写进 JSON `hosts[]`。

修法：所有列一律写非空占位符 `-`（`${pinned:--}`）。实测 `not-a-submodule` 宿主
ACTION 由 `skip:N` 修正为 `skip:not-a-submodule`。

## 兼容性

向后兼容。新增状态值与 JSON 字段均为**追加**语义。唯一需要留意的是 `--check` 退出码 `2` 的含义
由「有落后 / 需人工介入」扩为「有落后 / 半套接入 / 需人工介入」——但对消费者而言，`2` → `--apply`
的处置方式**依然正确**（这两类状态都能被 `--apply` 修复）。

宿主调用链（`archive_upload.sh` / `pgy_upload.sh` / `link-skill.sh`）**零改动**。

## 验证

- 双解释器语法（`/bin/bash` 3.2.57 + Homebrew bash 5.3.15）+ CJK 花括号静态检查（排除注释）
- 4 形态夹具：半套接入(引擎 HEAD) / 半套接入+落后 / vendored 反向对照 / 正常宿主
- **新克隆 A/B 对照**（决定性）：修复前 clone → 子模块目录不存在；修复后 clone → 存在且 pin 正确
- 边界：宿主脏跳过、子模块脏跳过（其本地改动保留）、`--allow-dirty` 处理且不卷入宿主其它改动、
  `--allow-downgrade` 让「未登记 + ahead」也按目标补登、`--no-commit` 得 `registered-staged`、连跑两次幂等
- 真实名单（3 宿主）回归：`--check` 退出码 0、`--json` 条目数 3、`--apply` 零动作
