# v1.1.0 — 本机多宿主同步器（`.local` 名单模式）+ WebBrowser 接入收敛

- 类型：功能变更（新增能力）
- 日期：2026-09-19
- 关联：CR-004（本版主体）、CR-003（同批规范性变更，无版本变更）
- 状态：代码与文档已落地；**引擎 commit 尚未 push origin**（见「已知限制」）

## 背景

v1.0.0 建立了治理基线，也把「引擎以 submodule 被多项目共享」这一事实写实了。但基线之后暴露出一件事：
**共享机制本身缺少「跟随同步」这一环**。三个宿主实际跑出了三种状态：

| 宿主 | 变更前状态 | 量化 |
| --- | --- | --- |
| `xiyuScoreboard` | submodule，但 gitlink 长期未更新 | 落后引擎 HEAD **4 个 commit**（缺治理基线、`STATUS.md`、`changelog/`、`experience/`） |
| `xiyu_todo_list` | submodule 只 add 未 commit | gitlink 仅存在于索引，HEAD 中无 `.gitmodules`、无 gitlink（落后 3 个） |
| `xiyuWebBrowser` | **退化为文件复制**并漂移 | 无版本锚点；`skill/SKILL.md` 与引擎不一致；缺治理目录；**密钥混在引擎目录内** |

也就是说：机制本身没问题（submodule 是对的），缺的是**让机制不容易被绕过、且成本低到不会退化的操作面**。
同期做了一次「submodule vs 软链共享」评估，结论是软链能消除更新摩擦但会牺牲版本锚点、并行版本与可复现性，
故本版采用折中：**保留 submodule 作为锁定层，另加本机名单做批量同步**。

## 内容

1. **`sync-hosts.sh`（新增入口）** — 本机多宿主跟随同步器：
   - `--check`（默认，只读）/ `--json`（单行结构化，供 AI/CI 解析）/ `--list`
   - `--apply`（更新各宿主 gitlink 并本地 commit；`--no-commit` 只 stage）/ `--dry-run` / `--only` / `--allow-dirty`
   - `--from-origin`：目标取 origin 默认分支（默认取**本机 HEAD**，引擎刚提交未 push 也能跟随）
   - `--add` / `--remove`：维护本机名单
   - `--install-hook [--auto]` / `--uninstall-hook`：可选在引擎仓提交后自动跟随（默认仅提示）
2. **`.local/hosts.json`（本机私有，gitignored）** — 需跟随引擎迭代的项目名单（name / path / submodule）。
3. **`.gitignore`** — 追加 `.local/`。
4. **文档债清理（随本版一并关闭）**：
   - `jq` 硬依赖补登进 `README.md` 与 `skill/SKILL.md`（关闭 `OPEN-003`）
   - README 文件树补全（关闭 `OPEN-004`）
5. **`xiyuWebBrowser` 接入收敛**（CR-003）：文件复制 → submodule；凭证目录与引擎目录分离；包装脚本移出引擎目录；Xcode Build Phase 显式传 `--config`。

## 效果

- 引擎迭代后，一条 `bash sync-hosts.sh --apply` 即把本机所有登记宿主推到同一引擎版本（宿主侧仅本地 commit，不 push）。
- 「宿主落后多少」从口头约定变成可体检、可 JSON 化的硬指标（`--check` 退出码：0=一致、2=有落后/需人工介入、1=出错）。
- 自动跟随可选开启（`--install-hook --auto`），且**默认不自动改任何仓库**——安全默认 + 显式提权。
- 三个宿主首次收敛到同一机制（均为 submodule），`xiyuWebBrowser` 的「密钥躺在引擎目录里」得到纠正。

## 兼容性

**向后兼容**：`archive_upload.sh` / `pgy_upload.sh` / `link-skill.sh` 的参数、默认值、输出 JSON 字段、退出码与生成物路径**零改动**；
宿主项目无需更新 gitlink 即可继续工作。新能力只在引擎仓本机使用，不进入宿主调用链。

## 已知限制

| 项 | 说明 |
| --- | --- |
| **引擎 commit 未 push**（`OPEN-005`） | 本机 HEAD 为 `6fadcb2`，`origin/master` 仍停在 `155046c`。`xiyuWebBrowser` 的 submodule 现 pin 在 `6fadcb2`，**人工 push 前，其它机器 / 新克隆无法初始化该子模块**（本机因从本地路径克隆而不受影响）。 |
