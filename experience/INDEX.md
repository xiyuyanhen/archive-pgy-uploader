# 执行经验库 — 使用说明

本目录存放项目的**可复用经验**，供 AI Agent 在每次任务前读取、任务后追加。

## 文件说明

| 文件 | 用途 | 更新方式 |
| --- | --- | --- |
| `LESSONS.md` | 结构化经验条目（人类可读） | **仅追加**，禁止删除或覆盖已验证条目 |
| `execution-log.json` | 机器可读执行日志 | 每次任务结束后追加一条记录 |

## Agent 必读时机

0. **动手之前**：阅读 `../STATUS.md` —— 目标范围、入口与调用、输入输出契约、依赖与约束、已知问题（`OPEN-NNN`）
1. **任务开始前**：阅读 `LESSONS.md` 全部「已验证」条目
2. **遇到异常时**：先查 `LESSONS.md`，再决定是否新增条目
3. **任务完成后**：总结经验 → 追加 `LESSONS.md` + `execution-log.json` → 按需走 `../STATUS.md` §8 变更流程

## 经验条目状态

| 状态 | 含义 |
| --- | --- |
| `verified` | 已在真实任务中验证有效，默认策略 |
| `fallback` | 备用方案，主策略失败时使用 |
| `deprecated` | 已过时，**不删除**，标注替代方案 ID |
| `pending` | 待更多任务验证，不可作为默认策略 |

## 修订原则

- **积累，不推翻**：新经验以追加方式写入；若旧经验不再适用，将其状态改为 `deprecated` 并注明 `superseded_by: L-XXX`
- **一事一证**：每条经验须关联至少一次真实执行记录（`execution-log.json` 中的 `run_id`）
- **变更须过状态文档**：改动前先读 `../STATUS.md` 确认现有实现；改动后同步更新 `STATUS.md`，
  并在 `../changelog/CHANGES.md` 追加 `CR-NNN` 条目；新问题须在 `STATUS.md` §7 分配 `OPEN-NNN` 编号
- **凭证不入库**：任何经验记录都不得包含 token / secret 明文
